# SFA.platform

دليل عملي سريع للمطور الجديد لفهم التطبيق وتشغيله محلياً.

## 1. وصف مختصر للتطبيق

`SFA.platform` هو تطبيق ويب مبني بـ React وVite باسم واجهة المستخدم "كوانت فيجن". يهدف التطبيق إلى مساعدة المستخدم على تحليل صورة شارت تداول عبر Gemini، ثم استخراج قيم رقمية من الصورة مثل القمة، القاع، ونقطة الاختراق، وبعدها يحسب مستويات فيبوناتشي وأهداف الصفقة مثل الدخول، جني الأرباح، ووقف الخسارة. كما يتيح طلب نصيحة عربية مختصرة من Gemini حول إدارة المخاطر والسيكولوجية بناءً على نتائج الصفقة.

> تنبيه: النتائج المعروضة تعليمية/مساعدة وليست توصية مالية مباشرة.

## 2. المتطلبات

قبل تشغيل المشروع تأكد من توفر التالي:

- **Node.js**: يفضل استخدام إصدار حديث متوافق مع Vite.
- **npm أو بديله**: مثل `pnpm` أو `yarn` لإدارة الحزم وتشغيل السكربتات.
- **مفتاح Gemini API**: يجب توفير مفتاح صالح لاستخدام Google Gemini API.

## 3. أين أجد المشروع وأين أنفذ الأوامر؟

المشروع موجود في مجلد المستودع نفسه. في هذه البيئة مساره هو:

```bash
/workspace/SFA.platform
```

يجب تنفيذ خطوات التثبيت والتشغيل من **جذر المشروع**؛ أي من المجلد الذي يحتوي على ملفات مثل `README.md` و`package.json` ومجلد `src`. إذا كنت تعمل من الطرفية، انتقل إليه أولاً:

```bash
cd /workspace/SFA.platform
```

بعد ذلك نفذ أوامر `npm install` و`npm run dev` من داخل هذا المجلد.

## 4. خطوات التشغيل

### 4.1 تثبيت الحزم

من جذر المشروع شغّل:

```bash
npm install
```

أو باستخدام بديل npm، مثل:

```bash
pnpm install
```

### 4.2 إنشاء ملف `.env`

أنشئ ملفاً باسم `.env` في جذر المشروع، ثم أضف متغير البيئة التالي:

```env
VITE_GEMINI_API_KEY=ضع_مفتاح_Gemini_هنا
```

يقرأ التطبيق هذا المتغير داخل الواجهة عبر `import.meta.env.VITE_GEMINI_API_KEY`، لذلك يجب أن يبدأ اسم المتغير بالبادئة `VITE_` حتى يكون متاحاً لتطبيق Vite في المتصفح.

### 4.3 تشغيل وضع التطوير

بعد تثبيت الحزم وضبط ملف البيئة، شغّل:

```bash
npm run dev
```

سيبدأ Vite خادم التطوير. افتح الرابط الذي يظهر في الطرفية، وغالباً يكون مثل:

```text
http://localhost:5173
```

## 5. شرح أهم الملفات

### `src/App.jsx`

الملف الرئيسي لمنطق وواجهة التطبيق. يحتوي على:

- حالات React الخاصة برفع الصورة، التحليل، الأخطاء، النتائج، والنصيحة.
- قراءة مفتاح Gemini وبناء رابط API.
- دالة رفع الصورة وتحويلها إلى Base64 للمعاينة والإرسال.
- دالة تحليل الصورة عبر Gemini لاستخراج `h1High` و`h1Low` و`m5Breakout`.
- حساب مستويات فيبوناتشي وأهداف الصفقة ونسبة المخاطرة للعائد.
- دالة طلب النصيحة النصية من Gemini بعد ظهور النتائج.
- مكونات العرض الصغيرة مثل بطاقات المؤشرات ومستويات فيبوناتشي.

### `src/main.jsx`

نقطة دخول تطبيق React. يقوم هذا الملف بتحميل `App`، واستيراد ملف الأنماط، ثم تركيب التطبيق داخل عنصر HTML ذي المعرّف `root` باستخدام `createRoot`.

### `src/styles.css`

ملف الأنماط العامة. يضبط الخطوط الافتراضية، لون النص والخلفية، وأبعاد الصفحة الأساسية مثل الحد الأدنى للعرض والارتفاع.

### `package.json`

ملف تعريف المشروع وإدارة الحزم. يحتوي على:

- اسم المشروع وإصداره ونوعه كـ ES Modules.
- سكربتات التشغيل:
  - `npm run dev`: تشغيل خادم التطوير عبر Vite.
  - `npm run build`: بناء نسخة الإنتاج.
  - `npm run preview`: معاينة نسخة الإنتاج محلياً.
- الاعتماديات الأساسية مثل `react` و`react-dom` و`vite` و`lucide-react`.

## 6. مسار العمل داخل التطبيق

مسار الاستخدام الأساسي يعمل كالتالي:

1. **رفع صورة**: يرفع المستخدم صورة لشارت التداول من واجهة التطبيق.
2. **تحليل Gemini**: يرسل التطبيق الصورة إلى Gemini ليقرأ القمة، القاع، ونقطة الاختراق من الشارت.
3. **حساب فيبوناتشي**: بعد استلام القيم الرقمية، يحسب التطبيق مستويات فيبوناتشي بين القمة والقاع.
4. **عرض النتائج**: يعرض التطبيق سعر الدخول، جني الأرباح، وقف الخسارة، البيع الأقصى، مستويات فيبوناتشي، ونسبة المخاطرة للعائد.
5. **طلب النصيحة**: يستطيع المستخدم طلب نصيحة إضافية من Gemini حول جودة الصفقة، إدارة المخاطر، والانضباط النفسي.


## 7. ما هو طلب السحب؟

طلب السحب، أو Pull Request، هو خطوة تُستخدم في GitHub أو منصات Git المشابهة لمراجعة التغييرات قبل دمجها في الفرع الرئيسي للمشروع. عندما يغيّر المطور ملفاً مثل `README.md` أو يضيف ميزة جديدة، ينشئ طلب سحب يحتوي على ملخص التغييرات والاختبارات التي تم تشغيلها. بعد ذلك يستطيع صاحب المشروع أو الفريق مراجعة التعديل، ترك ملاحظات، ثم الموافقة عليه ودمجه.

إذا كنت تعمل محلياً فقط ولا تستخدم GitHub، فليس عليك إنشاء طلب سحب. يكفي تعديل الملفات وتشغيل المشروع. أما إذا كنت تعمل ضمن فريق أو مستودع على GitHub، فسترفع التغييرات إلى فرع جديد ثم تفتح Pull Request للمراجعة.
